Linux 文件系统详解：目录结构、权限、目录挂载与硬盘挂载教程

← 返回知识库

Linux / 系统#知识库#Linux / 系统#Linux

这份教程面向需要上手 Linux 文件系统的零基础用户，完整讲解文件系统目录结构、文件权限管理、目录挂载（bind mount）和硬盘挂载四大块内容。文中命令以 Ubuntu 22.04/24.04/26.04 LTS 为例，同样适用于 Debian 等主流 Linux 发行版，照着操作即可完成。

学习原则：动手优先，边学边练。每条命令都亲手敲一遍，比看十遍教程更有效；挂载和分区操作会改动系统，**强烈建议先在虚拟机或测试机上练习**，熟练后再操作真实服务器。

文件系统目录结构

理解目录结构是入门 Linux 的关键一步。Linux 采用单一根目录树：所有文件都从根目录 / 开始，向下展开成一棵大树，没有 Windows 那样的 C 盘、D 盘。

认识 Linux 目录树

用 tree 命令可以直观看到目录树结构（未安装时先 sudo apt install tree）。Linux 根目录下的主要目录如下：

/
├── bin -> usr/bin        # 系统基本命令
├── boot                 # 内核与引导文件
├── dev                  # 设备文件（硬盘、U盘、终端等）
├── etc                  # 系统配置文件
├── home                 # 普通用户家目录
│   └── 你的用户名
├── media                # 可移动设备自动挂载点（U盘、光驱）
├── mnt                  # 临时手动挂载点
├── opt                  # 第三方商业软件
├── proc / sys           # 虚拟文件系统，反映内核与硬件状态
├── root                 # root 用户家目录
├── tmp                  # 临时文件，重启后通常清空
├── usr                  # 系统软件与共享文件
└── var                  # 动态数据：日志、缓存

重要目录详解

目录 作用 使用建议
/home 普通用户的个人目录，你的文档、图片、下载都在这（如 /home/你的用户名） 个人文件放这里，日常读写无需 sudo
/etc 系统配置文件目录，如软件源、网络、SSH 配置 改前先备份，改后一般需重启服务
/usr 系统安装的软件和共享文件 一般不要手动改动，交给包管理器
/var 经常变化的数据，如日志（/var/log）、缓存、网站数据 日志排查常看 /var/log/syslog
/tmp 临时文件，重启后通常被清空 不要放重要数据，随时可能丢失
/bin、/sbin 系统基本命令和系统管理命令（新版多为指向 /usr/bin 的软链） 命令所在位置，一般无需关心
/dev 设备文件，硬盘为 /dev/sda、/dev/sdb，分区为 /dev/sda1 挂载硬盘时在这里找设备名
/mnt、/media 挂载点：/mnt 手动临时挂载，/media 系统自动挂载可移动设备 挂载硬盘时建议在 /mnt 下建目录
/boot 内核、initrd 和引导程序文件 不要动，出错会导致无法开机
/proc、/sys 虚拟文件系统，实时反映内存、CPU、硬件状态 只读查看系统信息，不要写入

目录与文件操作常用命令

命令 作用 示例
pwd 显示当前所在目录 pwd
ls 列出目录内容；-l 详细、-a 含隐藏文件、-h 人性化大小 ls -lah
cd 切换目录；.. 上级、~ 家目录 cd /etc
mkdir 创建目录；-p 递归创建多级 mkdir -p a/b/c
touch 创建空文件或更新时间戳 touch note.txt
cp 复制；-r 递归复制目录 cp -r dir/ backup/
mv 移动或重命名 mv old.txt new.txt
rm 删除；-r 递归删目录，-f 强制 rm -rf tmp/
find 按名称、类型、大小搜索文件 find /home -name “*.log”
tree 以树状显示目录结构 tree -L 2 /etc
危险动作提醒：`rm -rf` 会静默删除且不可恢复，执行前务必确认路径正确，不要在重要目录（如 /home、/etc）下随手使用。

路径的表示方式

Linux 路径分为两种：绝对路径以 / 开头，从根目录写起；相对路径不写根目录，从当前位置算起。几个特殊符号需要记住：

  • ~：当前用户的家目录，cd ~ 等价于 cd /home/你的用户名。
  • .：当前目录，如 ./run.sh 表示执行当前目录下的脚本。
  • ..：上级目录，cd .. 返回上一级。
  • -：上一次所在目录，cd - 在两个目录间快速切换。
cd /etc          # 绝对路径进入 /etc
cd ..            # 回到上一级 /
cd ~             # 回到家目录
cd /var/log && cd -   # 进入 /var/log 再回到之前目录
阶段验证：能不看笔记完成新建目录、复制文件、用 find 搜索文件、在绝对路径和相对路径间切换，即视为通过。

文件权限教程

Linux 是多用户系统，每个文件和目录都有属主（owner）、属组（group）和一套读、写、执行权限，用来决定谁能看、谁能改、谁能运行。权限管理是排查「Permission denied」和保障系统安全的基础。

用 ls -l 看懂权限

执行 ls -l 查看文件详细信息，第一列就是权限位。看一个典型输出：

-rw-r--r--  1  zhangsan  staff   1234  Oct 23 10:00  note.txt
drwxr-xr-x  2  zhangsan  staff   4096  Oct 23 10:00  mydir

从左到右各列含义：文件类型与权限位、链接数、属主、属组、大小、修改时间、文件名。第一列的 10 个字符拆解如下：

字符位置 含义
第 1 位 文件类型：- 普通文件、d 目录、l 软链接、b 块设备、c 字符设备
第 2～4 位 属主权限（u）：r 读、w 写、x 执行
第 5～7 位 属组权限（g）：该组内所有用户
第 8～10 位 其他用户权限（o）：以上两者之外的所有人

例如 -rw-r--r--：属主可读可写，属组和其他用户只可读，所有人都不能执行。用 ls -ld 目录名 可以查看目录本身的权限。

三种权限与数字表示

读 r、写 w、执行 x 分别对应数字 4、2、1，组合相加即可得到权限数字：

权限 对文件 对目录
r（4） 查看文件内容 列出目录内容（ls）
w（2） 修改文件内容 在目录中创建、删除、重命名文件
x（1） 执行文件（脚本、程序） 进入目录（cd）

权限数字按 属主/属组/其他 三位一组拼成三位数，如 rwxr-xr-x = 7+5+5 = 755，rw-r--r-- = 6+4+4 = 644。

chmod 数字法修改权限

语法：chmod 三位数字 文件或目录。

chmod 755 script.sh     # 属主全权限，属组和其他可读可执行
chmod 644 note.txt      # 属主可读写，其他人只读（文件默认推荐）
chmod 700 private_dir   # 仅属主可访问（私有目录推荐）
chmod -R 755 myproject  # -R 递归修改目录下所有内容
权限值 适用对象 含义
755 脚本、程序、网站目录 属主可写，其他人只读可执行
644 普通文件 属主可写，其他人只读
700 私密文件/目录（如 SSH 私钥） 仅属主可访问
600 密钥、密码文件 仅属主可读写
777 不推荐 所有人全权限，安全隐患大

chmod 符号法

符号法用 u（属主）、g（属组）、o（其他）、a（所有人）配合 +（加）、-（减）、=（设为）来修改，适合只调整某一项权限。

chmod +x script.sh       # 给所有身份加执行权限（最常用）
chmod u+x script.sh      # 只给属主加执行权限
chmod g-w note.txt       # 去掉属组的写权限
chmod o= readme.md       # 其他用户权限设为无（= 后留空）
chmod a+r data.txt       # 所有人加读权限
chmod -R u+rwX web/      # 递归：属主加读写，目录（大写X）加执行

chown / chgrp 修改属主与属组

只有 root 才能修改文件的属主。语法：chown 属主:属组 文件。

sudo chown zhangsan note.txt        # 属主改为 zhangsan
sudo chown zhangsan:staff note.txt  # 属主和属组一起改
sudo chown -R www-data:www-data /var/www  # 递归改网站目录
sudo chgrp staff note.txt           # 只改属组

umask 控制默认权限

新建文件默认权限 = 666 - umask，新建目录默认权限 = 777 - umask。查看和设置 umask：

umask          # 查看当前值，默认通常为 022
umask 022      # 结果：文件 644、目录 755（推荐）
umask 077      # 结果：文件 600、目录 700（更安全）

特殊权限：setuid、setgid 与粘滞位

除 rwx 外还有三种特殊权限，在权限位中用 s 或 t 显示：

特殊权限 作用 常见场景
setuid（4） 执行时以属主身份运行（如 /usr/bin/passwd） 普通用户改密码
setgid（2） 文件以属组身份运行；目录新建文件自动继承属组 团队共享目录
粘滞位（1） 目录内文件只能被属主或 root 删除 /tmp 目录权限为 1777 
chmod 4755 app          # 加 setuid，显示为 -rwsr-xr-x
chmod 2770 team_dir     # 加 setgid，目录内新文件自动归组
chmod 1777 /tmp         # 加粘滞位，所有人可写但只能删自己的
ls -ld /tmp             # 输出 drwxrwxrwt，末尾 t 即粘滞位

权限问题排查：Permission denied

遇到 Permission denied 时，按顺序排查：

  1. 确认当前用户：whoami，不是 root 时系统文件用 sudo 执行。
  2. 查看权限：ls -ld 路径，确认属主、属组是否与当前用户匹配。
  3. 进入目录需要 x 权限：没有目录的 x 权限就无法 cd 进去，即使文件本身可读。
  4. 检查挂载点：mount 查看是否以只读（ro）方式挂载。
  5. 确认没有特殊限制：如 noexec 挂载选项会禁止执行文件。
ls -ld /var/www          # 查看目录权限
sudo chown -R www-data:www-data /var/www   # 修正属主
chmod -R 755 /var/www    # 修正目录权限
mount | grep /var/www    # 检查挂载方式是否只读
阶段验证：能用数字法和符号法修改权限、能修改属主属组、能解释 ls -l 输出的每一位、能独立排查 Permission denied，即视为通过。

目录挂载教程

挂载（mount）是 Linux 的核心概念：把一块存储设备（分区、U盘）或一个目录接入到目录树的某个目录上，这个目录称为挂载点。挂载后，访问挂载点就等于访问被挂载的存储内容。

查看当前挂载情况

系统启动时会自动挂载根分区等设备，用以下命令查看：

mount              # 列出所有已挂载的文件系统
df -h              # 查看各挂载点容量和使用率（最常用）
findmnt            # 树状显示挂载关系，更清晰
findmnt /etc       # 查看某个目录属于哪个文件系统

df -h 的输出中，Filesystem 列是设备名，Mounted on 列就是挂载点，例如根目录 /、家目录 /home 通常各自挂载在不同分区。

mount 基础语法

语法：sudo mount 设备或源 挂载点，卸载用 sudo umount 挂载点。

sudo mount /dev/sdb1 /mnt/data     # 把分区挂到 /mnt/data
sudo umount /mnt/data              # 卸载
sudo mount -o ro /dev/sdb1 /mnt/data   # 只读挂载

挂载点必须先存在：mkdir -p /mnt/data。挂载是临时的，重启后失效，需要永久挂载请见下文 /etc/fstab。

目录挂载（bind mount）

bind mount 可以把一个目录挂载到另一个目录，让两个路径指向同一份数据，不复制文件、不占额外空间。适合：把数据目录映射到约定位置、给容器/服务提供统一路径、备份时临时把目录挂到别处。

flowchart LR
    A["真实数据目录<br>/data/source"] -- bind 挂载 --> B["挂载点<br>/mnt/backup"]
    B -. 读写同一份数据 .-> A

# 1. 准备两个目录
mkdir -p /data/source /mnt/backup

# 2. 临时 bind 挂载：两个路径指向同一份数据
sudo mount --bind /data/source /mnt/backup

# 3. 验证：两边内容完全一致
ls /data/source && ls /mnt/backup

# 4. 卸载 bind 挂载
sudo umount /mnt/backup

也可以在源目录挂载后再叠加只读挂载，实现”原目录可写、备份入口只读”的效果：

sudo mount --bind /data/source /mnt/backup
sudo mount -o remount,ro,bind /mnt/backup   # 二次挂载设为只读

挂载后如何卸载

卸载用 umount，参数写挂载点或设备均可。如果提示 target is busy，说明有进程正在使用，先找出占用进程再卸载：

sudo umount /mnt/data

# target is busy 时：找出占用该目录的进程
lsof +D /mnt/data        # 列出打开该目录文件的进程
fuser -m /mnt/data       # 另一种查看方式

# 确认安全后强制卸载（慎用，可能影响正在写入的数据）
sudo umount -l /mnt/data

/etc/fstab 永久挂载

写入 /etc/fstab 后，系统每次开机都会自动挂载。每一行有 6 个字段：

字段 含义
设备 建议用 UUID（blkid 查询）而不是 /dev/sdb1，设备名重启后可能变化
挂载点 如 /mnt/data，目录必须已存在
文件系统类型 ext4、xfs、ntfs、swap；bind 挂载写 none
挂载选项 defaults、ro、noexec、bind 等，多个用逗号分隔
dump 是否备份，填 0
fsck 开机检查顺序，根分区为 1，其他为 2，不需要为 0 
# 编辑 /etc/fstab（改前先备份）
sudo cp /etc/fstab /etc/fstab.bak
sudo vim /etc/fstab

# 追加一行：数据盘开机自动挂载到 /mnt/data
UUID=xxxx-xxxx-xxxx  /mnt/data  ext4  defaults  0  2

# 追加一行：bind 目录永久挂载（类型写 none，选项写 bind）
/data/source  /mnt/backup  none  bind  0  0

# 保存后执行，立即按 fstab 挂载并验证（不报错即配置正确）
sudo mount -a
fstab 写错可能导致系统开机进入紧急模式。每次修改后先用 `sudo mount -a` 验证，确认无误再重启；开机进入紧急模式时，可输入 root 密码后用 `mount -o remount,rw /` 重新挂载根分区，再修正 fstab。

硬盘挂载教程

新买的硬盘插上后并不会自动可用，需要完成「识别 → 分区 → 格式化 → 挂载 → 永久化」五个步骤。下面以新增一块 /dev/sdb 硬盘为例完整演示。

flowchart LR
    A["识别硬盘<br>lsblk / fdisk -l"] --> B["分区<br>fdisk /dev/sdb"]
    B --> C["格式化<br>mkfs.ext4 /dev/sdb1"]
    C --> D["挂载<br>mount /dev/sdb1 /mnt/data"]
    D --> E["永久挂载<br>写入 /etc/fstab"]
    E --> F["验证<br>mount -a & df -h"]

识别新硬盘

用 lsblk 查看磁盘和分区信息，用 fdisk -l 查看磁盘容量和型号：

lsblk          # 树状显示，sda 系统盘，sdb 新硬盘
fdisk -l       # 查看所有磁盘的容量和分区表
dmesg | tail   # 查看内核识别硬件的日志

新硬盘通常显示为 sdb（第一块 sda、第二块 sdb、第三块 sdc，依此类推），NVMe 硬盘显示为 nvme0n1。确认没有数据后继续。

分区

使用 fdisk 交互式分区：

sudo fdisk /dev/sdb   # 注意是磁盘名，不是分区名

# 交互输入（每步回车确认）：
n      # 新建分区
p      # 主分区（primary）
1      # 分区编号 1
回车    # 起始扇区用默认
回车    # 结束扇区用默认（整块盘一个分区）
w      # 写入分区表并退出

# 写入后查看结果
lsblk    # 应看到 sdb1 分区

如果硬盘超过 2TB 需要 GPT 分区表，用 parted：sudo parted /dev/sdb mklabel gpt。

格式化

分区后必须创建文件系统（格式化），常用 ext4（通用）和 xfs（大文件、高并发）：

sudo mkfs.ext4 /dev/sdb1          # 格式化为 ext4
sudo mkfs.xfs /dev/sdb1          # 或格式化为 xfs
sudo mkfs.ext4 -L data /dev/sdb1 # -L 给分区设置标签
格式化会**清空分区上的全部数据**，执行前必须再三确认分区号正确，别把系统盘（sda）格了。

临时挂载新硬盘

sudo mkdir -p /mnt/data          # 创建挂载点
sudo mount /dev/sdb1 /mnt/data  # 挂载
df -h                           # 验证：应看到 /dev/sdb1 挂载在 /mnt/data
cd /mnt/data && touch test.txt  # 验证可读写

永久挂载（UUID + fstab）

设备名 /dev/sdb1 在重启后可能变化，永久挂载推荐使用 UUID（全局唯一标识）：

# 1. 查询分区 UUID
sudo blkid /dev/sdb1
# 输出类似：/dev/sdb1: UUID="2f8a1c0e-..." TYPE="ext4"

# 2. 备份并编辑 fstab
sudo cp /etc/fstab /etc/fstab.bak
sudo vim /etc/fstab

# 3. 追加一行（用上一步查到的真实 UUID）
UUID=2f8a1c0e-xxxx-xxxx  /mnt/data  ext4  defaults  0  2

# 4. 验证：立即挂载并检查
sudo mount -a
df -h

# 5. 验证通过后可以安全重启测试

创建 swap 交换空间

内存不足时系统会使用 swap。推荐用文件方式创建，避免重新分区：

# 1. 创建 2G 交换文件
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile

# 2. 格式化为 swap 并启用
sudo mkswap /swapfile
sudo swapon /swapfile
free -h        # 验证 Swap 已生效

# 3. 永久生效：在 /etc/fstab 追加
/swapfile  none  swap  sw  0  0

常见故障排查

报错 原因与解决
mount: wrong fs type 分区未格式化，或类型写错；先 mkfs 格式化，确认 fstab 类型字段
target is busy 有进程占用挂载点；用 lsof / fuser 找出进程，结束后再 umount
no such file or directory 挂载点目录不存在；先 mkdir -p 创建
permission denied 普通用户写系统挂载点；用 sudo，或挂载时指定 uid/gid 选项
开机进入紧急模式 fstab 写错；输入 root 密码，执行 mount -o remount,rw / 后修正 fstab

综合演练：把新硬盘挂载为数据目录

  1. 识别：lsblk 确认新硬盘设备名（如 sdb）。
  2. 分区：sudo fdisk /dev/sdb，输入 n、p、1、两次回车、w。
  3. 格式化：sudo mkfs.ext4 /dev/sdb1。
  4. 建挂载点：sudo mkdir -p /data。
  5. 临时挂载：sudo mount /dev/sdb1 /data。
  6. 查 UUID：sudo blkid /dev/sdb1 复制 UUID。
  7. 写 fstab：备份后追加 UUID=... /data ext4 defaults 0 2。
  8. 验证：sudo mount -a 无报错，df -h 看到挂载，重启后仍生效。
阶段验证：能独立完成一块新硬盘从识别到永久挂载的全流程，会查 UUID、会写 fstab、会用 mount -a 验证、能处理常见挂载报错，即视为通过。
