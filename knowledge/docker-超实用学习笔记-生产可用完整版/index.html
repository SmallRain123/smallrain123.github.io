Docker 超实用学习笔记（生产可用完整版）

← 返回知识库

Docker / 容器#知识库#Docker / 容器#Docker

1.1 镜像 Image

  • 只读模板，用来创建容器
  • 分层存储、可复用、可缓存
  • 类比：安装包 / 系统模板

1.2 容器 Container

  • 镜像的运行实例（读写层）
  • 容器删除，读写数据丢失（除非挂载卷）
  • 容器本质：进程隔离 + 文件系统隔离

1.3 仓库 Registry

存放镜像：Docker Hub / 私有 Harbor

1.4 核心优势

  • 一次构建、到处运行（解决环境问题）
  • 秒级启动、资源占用低
  • 环境一致性：开发、测试、生产统一

二、Docker 安装与基础环境

2.1 核心组成

  • Docker Client：命令行工具 docker
  • Docker Daemon：后台服务 dockerd
  • Containerd：容器运行时
  • Runc：真正启动容器进程

2.2 国内镜像加速（必配）

/etc/docker/daemon.json

{
  "registry-mirrors": [
    "https://docker.mirrors.ustc.edu.cn",
    "https://hub-mirror.c.163.com"
  ]
}

重启生效：

systemctl daemon-reload
systemctl restart docker

三、Docker 高频命令（工作 95% 场景）

3.1 信息查看

docker version      # 版本信息
docker info         # 系统信息
docker --help       # 帮助

3.2 镜像命令

docker images                 # 查看本地镜像
docker pull 镜像名:tag        # 拉取镜像
docker rmi 镜像ID             # 删除镜像
docker build -t 名字:tag .    # 构建镜像
docker save 镜像名 -o xxx.tar # 导出镜像
docker load -i xxx.tar        # 导入镜像

3.3 容器常用命令（重中之重）

docker ps                    # 查看运行中容器
docker ps -a                 # 查看所有容器（含停止）
docker start 容器名/ID
docker stop 容器名/ID
docker restart 容器名/ID
docker rm 容器名/ID           # 删除停止容器
docker rm -f 容器名/ID        # 强制删除运行容器

3.4 运行容器标准模板（生产通用）

docker run -d \
  --name=服务名 \
  --restart=always \
  -p 宿主机端口:容器端口 \
  -v 宿主机目录:容器目录 \
  镜像名:tag

参数解释：

  • -d：后台运行
  • --name：指定容器名
  • --restart=always：开机/宕机自动重启
  • -p：端口映射
  • -v：数据挂载（持久化）

3.5 进入容器、日志、排查

docker exec -it 容器名 bash    # 进入运行容器
docker logs 容器名              # 查看日志
docker logs -f 容器名           # 实时日志
docker logs -f --tail 200 容器名 # 尾部200行实时

3.6 容器详细信息 inspect（你刚学的）

# 完整信息
docker inspect 容器名

# 极简模板查询（超级实用）
docker inspect --format '运行状态={{.State.Running}} 退出码={{.State.ExitCode}}' 容器名

四、Docker 退出码含义（排错神器）

工作中最常见 3 个：

  • Exit 0：正常退出、手动关闭
  • Exit 1：程序代码异常、启动报错
  • Exit 143：被系统/用户 SIGTERM 优雅终止（不是崩，是被停）
  • Exit 137：被 OOM / 强制 kill -9 杀掉（内存不足）

五、Docker 数据持久化（必懂）

5.1 三种挂载方式

  1. 绑定挂载 -v 宿主机:容器：生产最常用
  2. 数据卷 volume：docker 管理目录
  3. 临时文件系统：临时数据

核心结论：不挂载 = 容器删除数据全丢

六、Docker 网络（面试+生产重点）

6.1 四种网络模式

  • bridge（默认）：桥接，容器独立 IP，端口映射访问
  • host：共用宿主机网卡，无端口映射，性能最高
  • none：无网络，隔离环境
  • 自定义网络：容器间可通过容器名互相通信

6.2 常用网络命令

docker network ls
docker network create 网络名
docker network connect 网络名 容器名

七、Dockerfile 镜像构建（开发必备）

7.1 核心指令

  • FROM：基础镜像
  • WORKDIR：工作目录
  • COPY / ADD：复制文件
  • RUN：构建时执行命令
  • EXPOSE：声明端口（仅声明，不生效）
  • CMD：容器启动默认命令（可被覆盖）
  • ENTRYPOINT：入口命令（不可被覆盖）

7.2 最简标准示例

FROM python:3.12
WORKDIR /app
COPY . .
RUN pip install -r requirements.txt
EXPOSE 8000
CMD ["python","main.py"]

八、Docker Compose 多容器编排

8.1 核心优势

一条命令启动/关闭整套服务，不用写冗长 docker run

8.2 常用命令

docker compose up -d    # 启动服务
docker compose down     # 停止并删除容器
docker compose logs -f  # 查看日志
docker compose restart  # 重启

8.3 通用模板

version: "3.8"
services:
  app:
    image: xxx:latest
    ports:
      - "8000:8000"
    restart: always
    volumes:
      - ./data:/app/data

九、生产避坑总结（精华）

  • 所有服务必须加 –restart=always，否则宕机不重启
  • 重要数据必须 -v 挂载持久化
  • 端口冲突优先检查：ss -tulpn | grep 端口
  • 容器异常先看：exitCode -> 再看日志
  • 尽量使用 compose 管理，不裸跑 docker run
  • 镜像一定要指定版本，不要用 latest 生产

十、你刚学的 docker inspect 精选模板（收藏版）

# 查看运行状态、退出码、是否OOM
docker inspect --format '状态={{.State.Status}} 运行={{.State.Running}} 退出码={{.State.ExitCode}} OOM={{.State.OOMKilled}}' 容器名

# 查看重启策略
docker inspect --format '重启策略={{.HostConfig.RestartPolicy.Name}}' 容器名

# 查看端口
docker inspect --format '{{.HostConfig.PortBindings | json}}' 容器名

# 查看完整启动命令
docker inspect --format '{{.Config.Entrypoint}} {{.Config.Cmd}}' 容器名
