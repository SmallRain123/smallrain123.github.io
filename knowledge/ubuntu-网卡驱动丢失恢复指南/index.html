Ubuntu 网卡驱动丢失恢复指南

← 返回知识库

Linux / 系统#知识库#Linux / 系统#Ubuntu

网卡驱动问题在 Ubuntu 系统中并不罕见，可能发生在内核升级、系统更新或硬件更换后。当网卡驱动”掉”了，最直接的表现就是无法连接网络，这给问题排查带来了挑战——你需要通过网络获取驱动，但网络却已断开。本指南将从离线诊断到恢复的完整流程，帮助你应对这一棘手场景。

一、问题确认与诊断

1.1 确认网卡硬件状态

首先确认系统是否识别到网卡硬件：

# 查看所有网络接口
ip link show

# 或者使用更详细的命令
lspci | grep -i network
lspci | grep -i ethernet

如果 lspci 能识别到网卡设备，但 ip link show 没有显示对应的网络接口（如 eth0、enp3s0 等），很可能是驱动问题。

1.2 检查驱动加载状态

# 查看已加载的网卡驱动模块
lsmod | grep -i ethernet
lsmod | grep -i wifi

# 检查内核日志中的网卡相关信息
dmesg | grep -i ethernet
dmesg | grep -i network
dmesg | grep -i firmware

如果看到类似 firmware: failed to load 的错误信息，说明驱动或固件缺失。

1.3 使用硬件信息工具

# 获取详细的硬件信息
sudo lshw -C network

# 查看 USB 网卡（如果有）
lsusb | grep -i network

二、确定网卡型号与所需驱动

2.1 识别网卡具体型号

# 查看网卡详细信息
lspci -nnk | grep -i net -A 3

# 输出示例：
# 03:00.0 Ethernet controller [0200]: Realtek Semiconductor Co., Ltd. RTL8111/8168/8411 PCI Express Gigabit Ethernet Controller [10ec:8168] (rev 0c)
#   Subsystem: Lenovo Device [17aa:3802]
#   Kernel driver in use: r8169

记录下：

  • 网卡厂商（如 Realtek、Intel、Broadcom）
  • 网卡型号（如 RTL8111、I219-V）
  • 设备 ID（如 10ec:8168）

2.2 确认所需驱动

根据网卡型号，可以通过以下方式确认驱动：

# 在线查询（需要网络）
modinfo r8169  # 替换为对应驱动名称

# 或者访问 Linux 内核官网查询
# https://cateee.net/lkddb/web-lkddb/

常见网卡及其驱动对应关系：

网卡型号 常用驱动模块
Realtek RTL8111/8168 r8169 / r8168
Intel I219-V e1000e / igb
Intel I210 igb
Broadcom BCM43xx b43 / broadcom-wl
Atheros AR9xxx ath9k / ath10k

三、恢复方案

方案 A：内置驱动重新加载（推荐尝试）

许多情况下，Ubuntu 内核已经包含了网卡驱动，只是模块没有正确加载。

3.1 尝试手动加载驱动模块

# 查找可用驱动模块
find /lib/modules/$(uname -r)/kernel/drivers/net -name "*.ko" | grep -i ethernet

# 尝试加载常见驱动（根据你的网卡型号）
sudo modprobe r8169  # Realtek
sudo modprobe e1000e # Intel
sudo modprobe igb     # Intel I210/I211
sudo modprobe atl1c   # Atheros

3.2 检查驱动是否加载成功

# 查看模块是否加载
lsmod | grep r8169

# 查看网卡接口是否出现
ip link show

如果网卡接口出现，说明驱动加载成功。接下来配置网络：

# 启动网络接口
sudo ip link set enp3s0 up  # 替换为你的接口名

# 配置 IP 地址（DHCP）
sudo dhclient enp3s0

3.3 设置开机自动加载

如果手动加载成功，可以设置为开机自动加载：

# 将驱动添加到 /etc/modules
echo "r8169" | sudo tee -a /etc/modules

方案 B：安装厂商官方驱动

内置驱动不兼容或性能不佳时，需要安装厂商提供的官方驱动。

3.4 准备工作（离线场景）

由于网络已断开，需要通过 USB 闪存等介质准备驱动文件：

  1. 在其他联网的 Ubuntu 机器上下载驱动包

    # 下载驱动包及依赖
apt download r8168-dkms linux-headers-$(uname -r)
apt download dkms build-essential

  2. 将 .deb 文件复制到 U 盘

3.5 离线安装驱动

  1. 挂载 U 盘

    sudo fdisk -l  # 查看 U 盘设备名，如 /dev/sdb1
sudo mkdir /mnt/usb
sudo mount /dev/sdb1 /mnt/usb

  2. 安装驱动包

    cd /mnt/usb
sudo dpkg -i *.deb

  3. 编译并加载驱动

    # DKMS 会自动编译并注册驱动模块
sudo dkms autoinstall

# 手动加载驱动
sudo modprobe r8168

3.6 验证驱动安装

# 检查驱动版本
modinfo r8168 | grep version

# 确认网卡状态
ip link show

方案 C：从源码编译驱动（最后手段）

如果无法找到预编译的驱动包，需要从源码编译。

3.7 下载源码

在联网机器上下载源码：

  • Realtek: https://www.realtek.com/en/component/zoo/category/network-interface-controllers-10-100-1000m-gigabit-ethernet-pci-express-software
  • Intel: https://www.intel.com/content/www/us/en/download-center/home.html

将源码压缩包通过 U 盘复制到目标机器。

3.8 编译安装

# 解压源码
tar -xvf r8168-8.051.03.tar.bz2
cd r8168-8.051.03

# 检查是否有编译工具
gcc --version
make --version

# 如果没有，需要先安装编译工具（离线安装依赖包）
# sudo dpkg -i build-essential_*.deb

# 编译驱动
sudo make clean
sudo make install

# 加载驱动
sudo modprobe r8168

四、网络配置恢复

驱动恢复后，需要配置网络连接。

4.1 使用 Netplan（Ubuntu 18.04+）

编辑 Netplan 配置文件：

sudo nano /etc/netplan/00-installer-config.yaml

示例配置（DHCP）：

network:
  ethernets:
    enp3s0:
      dhcp4: true
  version: 2

示例配置（静态 IP）：

network:
  ethernets:
    enp3s0:
      dhcp4: no
      addresses: [192.168.1.100/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]
  version: 2

应用配置：

sudo netplan apply

4.2 使用 NetworkManager（桌面版）

# 启动 NetworkManager 服务
sudo systemctl start NetworkManager
sudo systemctl enable NetworkManager

# 使用 nmcli 命令配置
sudo nmcli connection add type ethernet ifname enp3s0 con-name wired
sudo nmcli connection up wired

4.3 传统 ifupdown 方式（旧版本）

编辑 /etc/network/interfaces：

auto enp3s0
iface enp3s0 inet dhcp

重启网络服务：

sudo systemctl restart networking

五、常见问题排查

5.1 固件缺失错误

如果 dmesg 中出现 firmware: failed to load 错误：

# 安装固件包
sudo apt install linux-firmware

# 离线安装：下载 linux-firmware_*.deb 包
sudo dpkg -i linux-firmware_*.deb

5.2 驱动冲突

多个驱动模块可能冲突：

# 查看当前加载的驱动
lsmod | grep -i net

# 禁用冲突驱动
sudo modprobe -r r8169  # 卸载内置驱动
sudo modprobe r8168     # 加载新驱动

5.3 PCIe 电源管理问题

某些网卡受 PCIe 电源管理影响：

# 编辑内核启动参数
sudo nano /etc/default/grub

# 在 GRUB_CMDLINE_LINUX_DEFAULT 中添加
pcie_aspm=off

# 更新 GRUB
sudo update-grub
sudo reboot

5.4 USB 网卡作为临时解决方案

如果内置网卡实在无法修复，可以使用 USB 网卡临时联网：

# 查看 USB 网卡
lsusb
ip link show

# USB 网卡通常即插即用，无需额外驱动

六、预防措施

6.1 锁定内核版本

避免自动内核升级导致驱动失效：

# 查看已安装的内核
dpkg --list | grep linux-image

# 锁定当前内核版本
sudo apt-mark hold linux-image-$(uname -r)
sudo apt-mark hold linux-headers-$(uname -r)

6.2 备份驱动配置

# 记录当前加载的驱动
lsmod > ~/driver_backup.txt

# 备份 Netplan 配置
sudo cp /etc/netplan/*.yaml ~/netplan_backup/

6.3 创建恢复 U 盘

准备一个包含以下内容的恢复 U 盘：

  • 常用网卡驱动的 .deb 包
  • linux-firmware 包
  • 编译工具（build-essential）
  • 本指南的离线副本

七、故障速查表

症状 可能原因 快速检查 解决方案
ip link 无网卡接口 驱动未加载 lsmod | grep net modprobe <驱动名>
dmesg 显示固件错误 固件缺失 dmesg | grep firmware 安装 linux-firmware
驱动加载但无网络 网络未配置 ip addr 配置 Netplan
驱动编译失败 缺少编译工具 gcc --version 安装 build-essential
驱动加载后系统卡死 驱动冲突 lsmod 卸载冲突驱动

八、总结

网卡驱动丢失是一个可以通过系统性方法解决的问题。关键步骤包括：

  1. 准确诊断：确认是硬件识别、驱动加载还是网络配置问题
  2. 选择合适方案：内置驱动 → 官方驱动 → 源码编译
  3. 离线准备：提前准备恢复 U 盘是应对此类问题的关键
  4. 预防为主：锁定内核、备份配置可以避免类似问题

记住，Linux 社区有大量文档和经验可供参考。遇到疑难问题时，可以查看：

  • Ubuntu 官方文档：https://help.ubuntu.com/
  • Arch Linux Wiki（网络配置）：https://wiki.archlinux.org/title/Network_configuration/Wireless
  • 各网卡厂商官方技术支持
