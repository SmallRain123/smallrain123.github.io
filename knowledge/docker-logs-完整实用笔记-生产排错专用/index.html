docker logs 完整实用笔记（生产排错专用）

← 返回知识库

Docker / 容器#知识库#Docker / 容器#Docker

语法：docker logs [OPTIONS] 容器名/容器ID 容器日志默认存储在 json-file（默认驱动），就是你之前在inspect看到的 LogPath 文件。

常用参数

表格

✅ 基础玩法（直接复制）

# 输出全部日志
docker logs scrapling

# 实时跟踪日志（最常用）
docker logs -f scrapling

# 实时跟踪，只加载末尾200行（推荐，日志大不会卡顿）
docker logs -f --tail 200 scrapling

# 带时间戳实时查看
docker logs -f -t --tail 100 scrapling

✅ 按时间过滤（排查某时段报错神器）

时间格式：YYYY-MM-DDTHH:MM:SS

# 查看 2026-09-15 00:00 之后日志
docker logs --since="2026-09-15T00:00:00" scrapling

# 查看最近30分钟内日志（相对时间，超级好用）
docker logs --since 30m scrapling

# 查看 1小时前 ~ 10分钟前 的日志区间
docker logs --since 1h --until 10m scrapling

✅ 日志输出保存 & 过滤（管道配合 grep）

# 保存全部日志到文件
docker logs scrapling > scrapling.log

# 追加写入日志
docker logs scrapling >> scrapling.log

# 搜索关键字（查找error/Exception）
docker logs scrapling | grep -i error

# 实时跟踪同时过滤错误
docker logs -f scrapling | grep -iE "error|exception|fail"

# 只打印包含error的行，并带上时间戳
docker logs -t scrapling | grep -i error

-i忽略大小写；-E支持多正则匹配

✅ 结合 docker inspect 拿到日志路径，直接查看原始文件

# 获取日志文件路径
docker inspect --format '{{.LogPath}}' scrapling
# 直接tail原始日志文件
tail -f $(docker inspect --format '{{.LogPath}}' scrapling)

✅ 批量查看多容器日志

# 遍历所有容器打印名称+最后50行日志
docker ps -a --format '{{.Names}}' | xargs -I {} sh -c "echo ========== {} ========== ; docker logs --tail 50 {}"

⚠️ 日志驱动 & 日志清理（生产重点）

默认json-file会持续写日志，不限制会打满磁盘！ 查看当前容器日志配置：

docker inspect --format '{{.HostConfig.LogConfig | json}}' scrapling

方案 1：全局配置日志限额 /etc/docker/daemon.json

{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
  • max-size：单个日志文件上限
  • max-file：最多保留几个滚动日志 生效：
systemctl daemon-reload
systemctl restart docker

⚠️ 仅新创建容器生效，已有容器不会自动应用

方案 2：清理容器旧日志（临时清理，不推荐生产长期用）

# 截断日志文件（不要用rm直接删！docker还持有句柄）
truncate -s 0 $(docker inspect --format '{{.LogPath}}' scrapling)

❗常见坑

  1. docker logs 只看容器主进程 stdout/stderr，容器内部应用直接写本地文件的日志，docker logs看不到！需要挂载日志文件出来。
  2. 容器已经停止，依然可以docker logs查看停止前日志（只要容器没删除）。
  3. 日志巨大时不要直接docker logs，会一次性加载全部日志，导致服务器卡顿，必须加 –tail。
  4. 时间参数--since/--until在老版本 docker 不支持。

🧩 组合命令推荐（你 scrapling 容器直接用）

# 实时跟踪，末尾200行，带时间戳，过滤error
docker logs -f -t --tail 200 scrapling | grep -i error
